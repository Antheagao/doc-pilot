# doc-pilot agent rules

Project rules on top of the global ones in `~/.claude/AGENTS.md` (from the claude-brain repository).
Keep this file small: it loads on every session in this repository.
Longer procedures live in `.claude/skills/` and `.claude/commands/`.

## What this is

- A document-intelligence app: upload receipts and invoices, a vision model extracts structured fields with per-field confidence, low-confidence fields go to a human review queue, and corrections flow back into the evals.
- It is a local-only resume demonstration.
  It is never hosted or published to any server; `infra/terraform/` is kept as an infrastructure-as-code sample and is never applied.
- Two principles for new features (see `FUTURE.md`): the model reads, code computes (all arithmetic in `Decimal` code, never by the model), and every value points at its evidence.

## Orientation

- `PRESENT.md` is the current batch and task board, `FUTURE.md` the ranked roadmap, `PREVIOUS.md` the completed log, `UPDATES.md` the session log.
- The `/batch-loop` command (`.claude/commands/batch-loop.md`) works the board: planner, coder, deep-reviewer, one commit per task.
- `frontend/AGENTS.md` is generated by Next.js: Next.js 16 differs from training data, so read `frontend/node_modules/next/dist/docs/` before writing frontend code.

## Running it

- `docker compose up -d --build` starts PostgreSQL with pgvector (host port 5434), the API (`127.0.0.1:8000`), the worker, and the frontend (`http://localhost:3000`).
- Every route but `/healthz` needs a sign-in and there is no signup: create your user with `docker compose exec api python scripts/accounts.py create-user --email you@example.com` (it prompts for the password) and then `... add-member --organization default --email you@example.com --role owner`.
- The demo stack is a separate compose project: `backend\.venv\Scripts\python scripts/demos/demo.py stack up` (API 8100, frontend 3100, no host port for its database).
  Never point a destructive command at the dev project `doc-pilot`; its database volume was wiped once by a careless `down -v`.
- The Anthropic key lives in gitignored `backend/.env`, mirrored to the gitignored root `.env` for compose.
  `docker compose config` prints it in plain text, so never paste that output anywhere.
- Ports 5432, 5433, 5435, 5436, and 8080 belong to other local projects.

## Gates (the same commands CI runs)

- Backend, from `backend/` with `.venv`: `ruff check .`, `pytest -q` (the suite creates and migrates its own `docpilot_test` database).
- Demo scripts, from `backend/`: `ruff check ../scripts/demos`, `pytest ../scripts/demos -q`.
- Eval CLIs, from `backend/`: `ruff check ../evals`.
- Frontend, from `frontend/`: `npx eslint src`, `npm run build`.
- Evals: `tests/test_evals_runner.py` pins the mock extraction accuracy inside pytest; `evals/run_retrieval.py --check` gates retrieval quality; `evals/run_checks.py` runs the offline reconciliation eval.
- Compose: `docker compose config -q`, and with the demo overlay `docker compose -f docker-compose.yml -f docker-compose.demo.yml config -q`.
- Every model-touching feature ships with an eval before it ships to the demo.
  Live model runs are opt-in and cost-capped (`--max-cost`, `RUN_LIVE_SMOKE=1`, `DAILY_BUDGET_USD`).
- UI work is not done until it has been checked in a real browser, light and dark, 360px to 1440px, and every feature batch ends with its demo GIF (`FUTURE.md`).

## Commits

- One commit per task with a "why" message; subjects are plain descriptive sentences (see `git log`).
- Board updates (`PRESENT.md`, `PREVIOUS.md`, `FUTURE.md`, `UPDATES.md`) go in the same commit as the task they record.
- Stage exact paths, never `git add -A`; never commit `.env` files or anything matching a key pattern.
- Push to `master` after each task commit.
